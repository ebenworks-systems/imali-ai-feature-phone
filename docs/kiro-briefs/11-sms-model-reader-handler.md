GeminiReader takes { apiKey, model?, timeoutMs?, fetch? } (model defaults to "gemini-2.5-flash", timeout to 4000 ms, fetch to the global fetch so tests can pass a fake). It calls the generateContent REST endpoint once per message with the key in the x-goog-api-key header (never in the URL), asks for JSON only (responseMimeType application/json and a responseSchema), and tells the model it may only propose one of sale, expense, debt or payment, copying the amount and the customer name exactly as the owner typed them. It returns null on a timeout (AbortController), a non-200 answer, bad JSON or any other error, and never throws. It never logs the key or the owner's message.

The rule check on a proposal (requirement 47) lives outside GeminiReader, in src/ai/check.ts, so it applies to any reader: the amount substring and the customer substring must each occur in the owner's message (ignoring case), the amount substring must parse with parseAmount in the shop's currency to exactly the cents the proposal claims, the customer is required for debt and payment and refused for sale and expense, and anything else is refused. A refused proposal gives the unknown reply.
